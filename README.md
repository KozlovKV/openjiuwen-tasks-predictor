# Харнесс кодового агента на openJiuwen

Харнесс получает каталог с задачами и бюджет токенов и старается набрать максимум баллов. Главный принцип: **планирует и считает Python-код, который не тратит токены, а модель получает одну маленькую подзадачу в чистом контексте**. Ответ на задачу всегда даёт модель.

Каждый токен текста оплачивается при каждом вызове, поэтому общих инструкций вроде AGENTS.md здесь нет: системный промпт решателя занимает несколько десятков токенов.

## Сборка и запуск

```bash
docker build -t hack:latest .
```

Запуск идёт командой из регламента. Переменные окружения:

| Переменная | Значение |
| --- | --- |
| `LLM_BASE_URL`, `LLM_API_KEY` | адрес и ключ прокси, обязательны |
| `BUDGET` | бюджет в выходных токенах, по умолчанию 100000 |
| `WORKERS` | число параллельных сессий, по умолчанию 3, максимум 5 |
| `DEADLINE_SECONDS` | когда прекратить новые вызовы, по умолчанию 3300 |
| `TRAJECTORY_PATH` | куда писать траектории, по умолчанию не пишутся |

Ответы записываются в `<задача>/answer.txt` сразу после решения, поэтому принудительная остановка не теряет готовое.

Локальный запуск на копии задач с оценкой результата (адрес и ключ берутся из `../.env`):

```bash
python tools/run_local.py ПАПКА_С_ЗАДАЧАМИ --name dev --docker
```

## Как устроен прогон

1. **Проверки без токенов** (`harness/feasibility.py`) отсеивают заведомо невыполнимые задачи.
2. **Планировщик** (`harness/planner.py`) решает рюкзак: ценность равна `reward · P(выполнима) · P(решим)`, вес равен прогнозу расхода. Рюкзак пересчитывается после каждой задачи, внутри выбранного набора задачи идут по убыванию плотности ценности.
3. **Решатели** (`harness/solvers/`) готовят контекст кодом и делают обычно один вызов модели.
4. **Учёт** (`harness/ledger.py`) считает `completion + prompt/10` и резервирует худший случай до вызова, чтобы параллельные сессии не вышли за бюджет.

| Тип задачи | Что видит модель | Как проверяется |
| --- | --- | --- |
| `math` | условие; пишет программу, её запускает харнесс | программа пошаговая и использует все числа условия; при наличии свободных токенов ответ сверяется со второй моделью, при расхождении решает большинство с моделью с рассуждениями |
| `search` | только заметки с упомянутыми сущностями и связанные с ними | формат ответа |
| `data_analysis` | заголовок и первые строки файла; пишет программу | программа должна отработать без ошибки |
| `coding` | модули задачи (в больших проектах только части, связанные с падением) и сжатый отчёт о тестах; возвращает только изменённые функции, методы и константы, правки применяются по имени | локальные тесты после каждой правки, команда тестов берётся из условия |
| другие типы | `ReActAgent` с одним инструментом bash | для кодинга тесты |

Запасной путь на случай неудачи: до трёх попыток с текстом ошибки, сначала быстрая модель, затем модель с рассуждениями.

## Оценка расхода

Прогноз для задачи: `base + per_char · длина вопроса`, коэффициенты отдельны для каждого типа и уровня модели. Они лежат в `harness/estimator.json` и обучены скриптом `tools/fit_estimator.py` линейной регрессией по траекториям, с запасом 15%. В ходе прогона прогноз для каждого типа корректируется отношением фактического расхода к предсказанному.

Необязательные расходы, например проверка `math`, тратят только излишек: бюджет за вычетом прогноза на все задачи в очереди. Поэтому на малом бюджете проверки сами отключаются. Лимит на задачу равен минимуму из лимита типа и справедливой доли, зависящей от её баллов, поэтому задача за 1 балл не может съесть бюджет задачи за 5.

## Поиск невыполнимых задач

Неверный ответ стоит только токенов, а ошибочно пропущенная задача теряет награду. Поэтому задача отбрасывается бесплатно лишь при твёрдых признаках:

- нет упомянутого входного файла или каталога, нет заявленной колонки;
- сущности из вопроса нет в базе знаний;
- тест импортирует отсутствующий модуль, содержит противоречивые проверки или всегда падает;
- задаче нужен интернет, которого в контейнере нет.

Остальное отсекает сама попытка: модель может ответить `IMPOSSIBLE` в том же вызове. Такой ответ перепроверяется ещё одним дешёвым вызовом, потому что быстрая модель иногда сдаётся на решаемых задачах.

## Траектории и результаты

Все примеры организаторов выполнимы, поэтому тренировочный набор мы собрали сами: `tools/gen_tasks.py` воспроизводит формат примеров и добавляет 20% невыполнимых задач 12 видов. Сводка траекторий лежит в `trajectories/summary.jsonl`.

Результаты итогового образа с флагами регламента:

| Набор | Баллы | Расход | Время |
| --- | --- | --- | --- |
| 8 примеров организаторов | 20 из 20 | 603 токена | 16 с |
| 100 новых задач, seed 97 | 241 из 241 | 7 164 токена | 116 с |
| те же 100 задач, бюджет 3000 | 166 из 241 | 2 950 токенов | 55 с |
| 2 задачи из примеров, бюджет 400 | 7 из 7 | 154 токена | 4 с |
| 19 сложных coding-задач, из них 17 выполнимых | 51 из 51 | 2 814 токенов | 70 с |

Сложный набор составлен вручную для разовой проверки и в репозиторий не входит: классы, несколько модулей, константы, синтаксические ошибки, тесты в подкаталоге, скрытые тесты. На более ранних сборках промахи в обычных наборах были только в `math` (256 из 258 и 221 из 224 балла). Они привели к проверке формы программы, после которой 100 задач `math` дали 246 из 246 баллов. Сгенерированные задачи лишь приближают финальный набор, и настоящие результаты могут отличаться.

## Неочевидные детали

- Поле `expected` харнесс не читает: загрузчик берёт только `task_id`, `task_type`, `instruction` и `reward`. Его использует только `tools/score.py` для локальной оценки.
- Модельный код запускается с очищенным окружением, ключ прокси ему недоступен.
- Логи openJiuwen отключены от диска: по умолчанию он пишет в `./logs`, а `/app` доступен только для чтения. Данные токенизатора и байт-код подготовлены при сборке.
- Ответ 429 не считается ошибкой: харнесс ждёт указанное прокси время. Пять других ошибок подряд означают, что прокси перестал отвечать, и прогон завершается.
- Контейнер работает от root. С `--cap-drop ALL` это даёт право записи в каталог задач, только если он принадлежит root или открыт на запись всем.
- `DeepAgent` не используется: одни только секции его промптов занимают около 120 тысяч символов.
