# Заметки для команды

Этот файл нужен людям и их агентам при разработке. Харнесс его не читает, в образ он не попадает (см. `.dockerignore`). Устройство решения описано в `README.md`, здесь только решения, причины и подводные камни.

## Задача

Харнесс на openJiuwen получает 100 задач и бюджет около 100 000 выходных токенов (10 входных = 1 выходной, кеш не учитывается) и за час набирает максимум баллов. При равенстве баллов выигрывает меньший расход. Штрафа за неверный ответ нет. 15–25% задач невыполнимы.

## Принятые решения

Менять только после обсуждения.

- **Планирует код, отвечает модель.** Рюкзак, оценка расхода и подготовка контекста написаны на Python и не тратят токены. Общие инструкции в промпт не добавляем: текст оплачивается при каждом вызове. 1500 токенов при 300 вызовах стоят 45 000.
- **Ответ всегда даёт LLM.** Распознавать шаблоны задач регулярками и отвечать без модели мы сознательно не стали: это хрупко и плохо соответствует идее кодового агента.
- **Ответы пишутся в `<задача>/answer.txt`**, а не в `workspace/`.
- **Поля `expected` в финальных задачах нет.** Харнесс читает только `task_id`, `task_type`, `instruction`, `reward`. `expected` использует только `tools/score.py`.
- **Невыполнимую задачу пропускаем только при твёрдых признаках**, потому что ошибочный пропуск теряет баллы, а лишняя попытка стоит лишь токенов.
- **Необязательные траты идут только из излишка**: бюджет минус прогноз на всю очередь. Иначе можно провалить отборочный этап на двух задачах.
- **`DeepAgent` не используем**: одни секции его промптов занимают около 120 тысяч символов. Нужны только `Model` и `ReActAgent`.

## Как работать локально

- Нужен Python 3.11–3.13. На 3.14 openJiuwen не ставится.
- Файл `.env` лежит **на уровень выше репозитория** и содержит `OPENAI_BASE_URL` и `OPENAI_API_KEY`. В контейнере те же значения приходят как `LLM_BASE_URL` и `LLM_API_KEY`. Ключи в репозиторий не коммитим.
- Модели `kimi-k3` из примера `.env` на нашем тарифе нет. Доступны `qwen3.8-27b`, `qwen3.6-35b-a3b` и их варианты `-noreason`.
- Задачи и прогоны держим вне репозитория, `tools/run_local.py` работает на копии в `../runs`.

```bash
python tools/gen_tasks.py ../train-tasks --count 200 --seed 7
```
```bash
python tools/run_local.py ../train-tasks --name dev --docker
```
```bash
python -m unittest discover -s tests
```

После изменения решателей обновляйте оценщик: `python tools/fit_estimator.py ПУТЬ_К_ТРАЕКТОРИИ`. Один полный прогон на 100 задач стоит 7–10 тысяч токенов.

## Что выяснили на практике

- **Math:** быстрая модель ошибается, когда пишет задачу одним выражением: теряет шаг или путает приоритет операторов. Пошаговые программы надёжны, поэтому форма проверяется кодом. Вторая модель считается голосом, только если её программа тоже пошаговая.
- **`IMPOSSIBLE`:** модель иногда сдаётся на решаемых задачах, поэтому такой ответ перепроверяется одним дешёвым вызовом.
- **Лимиты прокси:** наш ключ разрешает 3 одновременных запроса, отсюда 3 воркера по умолчанию. Ответ 429 означает ожидание, а не исчерпание бюджета, иначе прогон оборвётся раньше времени.
- **Контейнер:** корень только для чтения, а openJiuwen по умолчанию пишет логи в `./logs`, поэтому `run_agent.py` отключает файловые логи до первого импорта. Данные tiktoken и байт-код подготовлены при сборке.
- **Модельный код** запускается с очищенным окружением, ключ прокси ему не виден.

## Открытые вопросы

- В опубликованной команде `docker run` нет `-e BUDGET`. Без переменной харнесс берёт 100000. Нужно подтвердить у организаторов.
- Контейнер работает от root при `--cap-drop ALL`, поэтому каталог задач должен принадлежать root или быть открыт на запись всем.
- Сгенерированные задачи только приближают финальный набор. На реальном прокси организаторов харнесс не проверялся.
- Ещё не проверены в контейнере: `ReActAgent` (незнакомые типы задач и запасной путь для coding), изолированная сеть, сложные coding-задачи.
